# ESPRIT PFE Report Guidelines

Reference for writing an ESPRIT "Projet de Fin d'Études" (PFE) report according to the school's official pedagogical note. Use this to guide structure, content, and formatting — whether drafting sections, outlining chapters, or reviewing a draft against the requirements.

## Overall goal and tone

- The report presents the work done during the PFE internship and highlights achievements and skills acquired.
- It must have a scientific character: rest on theoretical foundations and a rigorous methodology.
- Only describe work that was actually carried out — no padding with unrelated material.
- Company description should stay high-level, then focus specifically on the department/service where the PFE was carried out (not a generic company profile).
- Target length: ~40 pages, excluding annexes.
- Cover page: use ESPRIT's official template (not custom-designed).

## Core content — the report must clarify

- The problématique (problem/issue) established at the start of the internship.
- The student's precise mission and role within the host structure.
- Whether the work resolved the stated problématique.
- The means/approach used to get there.
- Day-to-day tasks performed during the internship.
- An evaluation of the internship's value from both a professional and personal angle:
  - What kind of experience and in which domains?
  - What did the student bring to the company, and what did the company bring to the student?
  - Were the internship's objectives met, for both the company and the student?

## Standard structure

1. **Page de garde** — official ESPRIT template.
2. **Remerciements** — a dedicated thank-you page.
3. **Introduction générale**
   - States the subject with precise information.
   - Poses the problem to be solved — without revealing results yet.
   - Once the problem is clear, briefly describes the overall approach toward the objective.
   - Briefly announces the content of each chapter.
4. **Développement des chapitres** (main body — can be split into parts/sub-parts)
   - Each chapter must connect logically to what precedes and follows it.
   - Chapter order/content should follow the methodology used for the project (its stages and models).
   - Each chapter contains:
     - An introduction presenting the chapter's content.
     - The chapter's development/body.
     - A conclusion summarizing key results and introducing the next chapter.
   - **Description du travail proposé**: presents the problem(s) concisely and pedagogically — assume the reader is not a specialist and doesn't know the project. Situate the assigned work in a broader context.
   - **Description du travail réalisé** (can span multiple chapters):
     - Include the internship/project work plan (planning) — ideally placed at the end of this section, on its own full page.
     - Describe difficulties encountered and any changes made to initial objectives.
     - Keep this section clear and understandable for a non-specialist: do NOT include code snippets — technical details belong in the annexes.
5. **Conclusion générale**
   - Highlights the work and the areas where the student progressed.
   - Should open up perspectives (future directions), not just close the topic.
   - Must include:
     - A recap of the overall approach announced in the introduction.
     - Presentation of results: answers to the problems posed at the start.
     - Problems encountered during the project.
     - Contributions (technical and other).
     - Perspectives for going deeper or broadening the subject; openings toward other experiences/research, or knowledge to share with future interns.
6. **Bibliographie / Netographie**
   - Full references: author name(s), title, journal/conference name, publisher, publication date, issue number or conference location, page numbers.
   - For web sources: also include the URL, the subject, the author(s), and the publication date if available.

## Formatting rules (mandatory)

| Element | Rule |
|---|---|
| Font | Times New Roman, 12 pt for body text |
| Margins | 2.5 cm (default) |
| Line spacing | 1.15 |
| Justification | Full justify (left and right) |
| Document title | 24 pt, centered |
| Pagination | Page number bottom-right, format "current/total". No page with only ~3 lines; avoid orphaned figures/illustrations on their own page |
| Printing | Recommend double-sided (recto-verso) if printed |
| Paragraphs | First-line indent of 0.50 cm; avoid excess white space (e.g. never end a chapter on a page with just a couple of lines) |
| Section titles | Bold; font size decreases with heading depth; numbered as 1, 1.1, 1.1.1, etc. Indent 0.20 cm from page edge; 0.30 cm hanging indent for wrapped title lines; 0.20 cm space between the number and the title text |
| Emphasis | Examples in italics; definitions boxed or otherwise set off; conclusions/key elements in bold |
| Figures/tables | Every figure (table, chart, illustration) needs a caption and an in-text reference. Number consistently by type: Tab. 1, Graph. 1, Fig. 1, etc. |
| Citations | Short quotations in guillemets (« ») |
| Sources | Always cite sources for definitions/analyses reused from elsewhere; list them at the end under "Bibliographie/Netographie" |

## How to use this when helping the user

- When drafting a chapter, follow the structure and tone rules above (no code in the body, pedagogical framing for a non-specialist reader, etc.) and point out that code/technical detail belongs in annexes.
- When reviewing a draft, check it against: required chapter structure, presence of a work plan, no code snippets in the body, proper figure/table captions and references, and correct citation of sources.
- When formatting a document (e.g. in Word), apply the formatting table above: Times New Roman 12pt, 1.15 spacing, justified text, numbered headings, 0.50 cm paragraph indents, bottom-right pagination.
- Always keep the introduction free of result reveals — results belong in the conclusion.
